# OnboardingCarousel (components/onboarding/OnboardingCarousel.tsx)

## Direction (current)
The whole of onboarding, on one surface: a horizontally paged beat per real workflow, each a media frame over a headline, a hook and a CTA that starts that workflow for real (ADR 0026). Three beats since arc v2 (2026-09-18), hook-first: break, track, bills. A fixed footer under the pager carries the progress dots and the ghost exit. Nothing here simulates the app, nothing auto-advances, and back never steps between beats.

Each beat is a vertical scroller, so the block centres itself while it fits and stays reachable when it does not. Built on plain platform `ScrollView`s with no reanimated work at all: two release builds have been crashed by animation on this codebase, and the first screen a user ever sees is the last place to spend that risk.

## States
- **Beat 1, break**: the landing state. Reach: `habitcents://onboarding/welcome`, or Profile > Start over.
- **Beat 2, track** and **beat 3, bills**: one and two pages right. Below the fold, reachable only by a swipe nothing on screen prompts; `onboarding_beat_viewed` counts who gets there.
- **Overflowing**: from AX4 up the block is taller than the pager and the beat scrolls, CTA included. Reach: `xcrun simctl ui <device> content_size accessibility-extra-extra-extra-large`, relaunch, open the route.

## Decisions
- 2026-09-18 (arc v2, onboarding story arc canvas): **hook-first, three beats: break, track, bills.** Why: the old order led with the commodity feature and hid the differentiated promise behind an unprompted swipe; the arc is now pain, turn, payoff. The custom-habit idea folds into the break sheet's own "Pick one or name your own". Bills promises Upcoming, deliberately not reminders (delivery does not exist; the beat's CTA opens the real add-bill sheet on Money, the one door that lands off Today). Copy pass in the same round: one idea per line, no rule-of-three lists, spoken contractions, the app's own words over generic ones ("Find your leak." / "Skip it, keep the money." / "Just the amount. We'll spot your leaks." / "Know what's coming." / "Your bills, a month ahead."). Old-order funnel comparability deliberately ends here; the 2026-09-17 carousel events are the new baseline.
- 2026-09-17 (onboarding audit): **each beat is a vertical `ScrollView`, centred by a pair of collapsing spacers.** Why: the beat was a fixed `View` with `justifyContent: 'center'`, so the only element able to absorb larger text was the text, and it pushed the CTA off the bottom. At AX1 the button was sliced in half by the footer; from AX3 up it was not on the screen at all, so the one control the screen exists to offer could not be tapped and every accessibility-text user was force-skipped through onboarding. The spacers (`flexGrow: 1, flexShrink: 1, flexBasis: 0` above and below) centre the block while there is slack and collapse to nothing when there is not. Rejected: `contentContainerStyle: { flexGrow: 1, justifyContent: 'center' }`, the obvious recipe, which centres overflowing content by pushing its top out of the scrollable area where no gesture reaches it. Also rejected for now: pinning the CTA below the pager, which is the stronger guarantee and would also fix the inter-beat jump under Open, but moves the button out of the beat and is a layout call that belongs with the media redesign.
- 2026-09-17: **line heights stay written at their 1x values.** Why: React Native scales `lineHeight` by the system font scale alongside `fontSize` whenever `allowFontScaling` is on. A first pass at the fix multiplied them here as well, which applied the scale twice; at AX1 the hook's leading came out near double its own text and the copy read as a list of lines rather than a sentence (caught on the simulator, not by the suite). Pinned in `__tests__/onboardingCarouselDynamicType.test.tsx` so the next reader who notices a "missing" scale does not add it back.
- 2026-09-17: **the carousel reports every beat settle through `onBeatViewed`; the screen dedupes and tracks.** Why: `onboarding_started` fires inside `completeStep('welcome')`, which only runs once a beat is picked, so it landed at the same instant as `onboarding_intent_selected` and nothing at all fired for the carousel being seen. The pick rate had no denominator and there was no way to tell a second beat nobody reaches from one nobody wants. Paging is what this component knows about and "seen once" is a funnel question, so the dedupe lives in `app/onboarding/welcome.tsx` with the rest of this flow's events. New: `onboarding_carousel_shown`, `onboarding_beat_viewed`.

## Open
- **The media frame is a placeholder and has been since build 14 (2026-08-14).** On a 393pt phone the "Preview coming soon" box is about 45% of the screen height and the first thing the eye lands on, so the largest, highest-contrast element of the first screen announces that the product is unfinished. The copy underneath is doing all the work. Charen is designing the media (2026-09-17); if it does not land, the layout should change rather than keep the hole.
- **The block jumps about 23pt between beats.** Beat 1's hook wraps to two lines and beat 2's to one, and the beat centres its content, so the media frame, headline and CTA all shift vertically on every swipe. In a carousel the frame and the button should be anchored and only the text should change. Not fixed in the Dynamic Type pass because the fix is either pinning the CTA or top-anchoring the block, both layout calls for the media redesign.
- **Does the carousel earn its swipes?** (Reframed 2026-09-18: at two beats the question was carousel versus fork; at three the fork answer is gone, but two of three beats still sit behind an unprompted swipe.) The `onboarding_beat_viewed` numbers answer it once real installs flow; if beats 2 and 3 go unseen, the beats need an on-screen reason to swipe or the arc needs to collapse.
- **VoiceOver hears each headline twice**: `BeatMedia` takes `accessibilityLabel={beat.headline}` and the headline then renders beneath it as a header. Separately, the CTA's `accessibilityHint` carries "Step n of total", a progress statement in the slot reserved for describing what the action does.
- The accessibility walk covered AX1, AX3 and AX5 on the iPhone 16 simulator. A 667pt phone (SE) at AX1 is unchecked, and so is Android.
