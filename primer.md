## Project overview

Expo / React Native (SDK 54) personal-finance + habits app. Local-only (AsyncStorage, no backend, no Plaid). Repo: `habitcents-mobile-app`. Identity: name `habitcents`, bundle id `com.habitcents.app`, light mode only.

## Current project state (2026-09-06)

Two sessions shipped today. The leak finder wrap and its receipt (#142, #144, #145) and the navigation wave (#143) are both on main and both ride TestFlight build 21.

Onboarding dropped to two beats. Zero code deleted, 273 scan tests still green (their suites mock the gate on). 1123 tests, tsc clean.
- **Debt that blocks the leak finder's ship: nothing can grant the six months the receipt promises.** `Entitlement` is `'free' | 'premium'` with no duration or expiry, the only grant path is the dev-menu-only `setMockEntitlement`, `getEntitlement()` is synchronous across eight call sites so an expiry must resolve inside that read, and there is no live RevenueCat client or backend. The opt-in is persisted with a timestamp, so the who and when exist; only the grant does not. Payments work: human gate, belongs with core-p3. On the umbrella punch list.
- **TestFlight build 21 queued from main 2026-09-06 with auto-submit** (internal profile). A native build was required because `eas.json` changed, which feeds the runtime fingerprint. It carries everything since build 20: the leak finder wrap and receipt, plus #143's filled tab glyphs and segment swiping on Money and Insights.
- **Navigation wave MERGED to main (PR #143, squash `5a66773`).** Two things shipped. **(1) The tab bar's selected state is a filled glyph and the pill is gone**, along with the 2.25 stroke gap, and `layout.tabBarHeight` went 64 back to 56 (those 8pt existed only to clear the pill). ADR 0037's requirement is unchanged and still binding, the selection must survive desaturation; filled-vs-outlined meets it by mass and was verified by desaturating a screenshot. `Wallet` and `TrendingUp` needed hand-authored filled variants in `components/ui/TabGlyphsFilled.tsx` because lucide silently deforms open paths when filled. **(2) Money and Insights swipe between their segments**, via `utils/useSegmentPager.ts`, which Today's inline pager moved into with zero behaviour change. Still a plain paging `ScrollView`: no gesture-handler, no Reanimated. The extraction fixed a latent bug present since ADR 0019 (only `onMomentumScrollEnd` was wired, so a slow drag desynced the control from the pane) and added index clamping for the three-page pager. New events `money_view_switched` / `insights_view_switched`, approved by Charen in-session per ADR 0035. 105 suites / 1123 tests, tsc clean, OTA-eligible.
- **Cross-page swipe was proposed and REJECTED**, with the six reasons written into `design/decisions/components/SegmentPager.md` so it is not re-proposed blind (invisible page boundary, per-tab segment counts differ, iOS back-gesture collision, needs a forbidden animation library, implies a sliding tab transition against the instant-switch rule, no VoiceOver benefit). A swipe past the last segment bounces.

## Dev

Quick start: `npm install` then `npm run web` / `npm run ios`. Tests: `npm test`. Type-check: `npx tsc --noEmit`.
To see the app populated with demo data: `git checkout dev/seed-data` then run (SEED_DEV_DATA flag in `utils/devSeed.ts`); return to `main` for a clean first-run.
